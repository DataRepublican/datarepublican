# 527s
527s are also known at Political Action Committees. They have a fairly simple format, it's a giant | delimited file. It's mostly well formatted, with one exception.
* newlines (\n) have not been escaped. So there's a script join_split_lines.py that knows the number of columns there should be in each type of record, and if it comes up short, it replaces the newline with \n, which heals most of the problems in the file. 
# File definitions: in /Volumes/Data/527
* irs_527_spec_1.py this lays out the format of a 1 record which creates the PAC. Key fields here are the EIN, Organization Name, and the pieces of the Mailing Address, Business Address, and Custodian Address. This corresponds to Form 8871 from the IRS it creates the PAC. 70880 of these. emails are also interesting, see seperate note about those.
* irs_527_spec_2.py a 2 record, This is essentially the header for the next set of records and 8872 form, which holds all the schedules for the PAC, and gives the PAC an opportunity to change addresses. 52212 of these (people form PACs and don't get any money)
* irs_527_spec_A.py an A record, this is a record of a contribution coming into the PAC. Key pieces here are the Contributor Name and Address Fields, and the Employer name 8.5M of these, dominated by the smurfing PACs of ActBlue and WinRed
* irs_527_spec_B.py this is a record of a contribution by PAC to a Candidate or other PAC or an expense, for our purposes, we'll treat them all as contributions. 7M of tehse
* irs_527_spec_D.py a D record, this is a record of a related entity, 175K of these, we'll ignore them for now. 
* irs_527_spec-E.py an E record, this is a record of an Election Authority ID number, which are issued by states. When you see one, I guess update a state_eain in the master PAC record. 16K of these
* irs_527_spec_[FHR].py file related metadata we don't care about. 
* The Form Id Number in the records allows you to join back to the source data, though the tile is setup to follow the initial 2 record, so mostly you just set the current PAC owner when you see a 2 record, and then read in the A/B records. 

# Email Addresses
* Email addresses can serve as a good proxy for an accurate Employer field which are sometimes omitted, but they're in reverse utility order: bob@foo.com is really com/foo/bob. So we should parse them, make sure they're real by looking for @, then split the domain and store domain0, domain1, domain3, username, full_email with all components reversed. Then we'll be able to do statistical analysis on common patterns.
